# 公共 MCP 安全与契约变更立即严格生效

本地工具优化调研确认了无边界来源读取、可绕过的更新并发门、静默丢弃 metadata 和绝对路径暴露等问题。下一次发布将直接强制新安全与契约要求，不提供 legacy warning 周期或可长期恢复旧行为的运行开关；迁移说明和本地配置工具可以帮助用户提前调整，但不允许请求在不满足新合同的情况下继续执行。

## 考虑过的方案

- 一个有明确终点的兼容发布：迁移更平滑，但仍会在兼容期保留已确认风险和双重合同。
- 长期 legacy 开关：短期破坏最小，但会永久扩大测试矩阵并允许不安全边界继续存在。

## 后果

- 旧配置和旧客户端调用可能在升级后直接失败，必须使用稳定、脱敏的错误码说明缺失的新要求。
- 实现不得在失败时静默回退到无来源边界、无并发门、忽略参数或返回绝对路径的旧行为。
- 发布说明、配置迁移命令和回滚文档仍是必需品；它们帮助迁移数据与配置，但不重新启用旧运行语义。

## 后续例外

- [ADR-0002](./0002-ingest-inherits-process-read-permissions.md) 明确决定不收紧 `wiki_ingest` 的来源读取权限；ADR-0001 的“立即严格”原则不适用于该项。

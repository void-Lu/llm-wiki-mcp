# Shared Spec Vault

这是一个用户显式触发的 skill。按阶段选择 `extract`（提取、维护或降级公共正文）、`import`（原文导入或项目适配）、`sync`（把项目规范镜像到知识库）。用户已授权连续工作时，可以串联这些阶段；每阶段明确读写方向。公共正文调整本身不授权回写项目，回写项目本身也不授权同步知识库。`sync` 只覆盖项目到知识库；知识库改动回写项目走 `import`。

## 准入与最小化

进入 `wiki/entities/shared-specs/` 遵循最小化：默认留在项目内，作为独立踩坑记录或项目特有规范、方案。只有多个项目都必须遵守的平台、工具或工程契约，才准入公共规范。

以下情况不进入公共规范：

- 某一项目的独立踩坑记录、历史事故或排查清单
- 某次业务或需求开发中的规格、方案或实现选择
- 仅某一项目采用的策略，或尚不确定是否跨项目成立的规则

多项目曾导入、标题相似、含可复用案例，或「以后可能用到」，都不足以作为准入理由。拿不准时先作为项目页提出，经用户确认后再提升；不默认保留或提升现有公共页。维护已有公共规范时，若不再满足准入条件，按降级处理，而不是默认留在 `shared-specs/`。

降级时：把正文迁到所属项目的踩坑记录或项目规范（已有项目正文则不覆盖、不新建重复页），再归档公共页；只改仍应指向新位置的链接。过期或已清理的项目规范被移除后，指南和索引删除对应条目即可，不要改链到其他项目或替代页。公共规范发生合并时，项目中的对应导入或副本按同样方式合并，再清理被吸收的旧页。细节见[文档迁移](references/document-migration.md)和[项目采用与适配](references/project-adoption.md)。

## 项目与工具入口

- 每个项目使用一个真实的规范来源目录。解析顺序：用户本次明确指定的路径、项目 `AGENTS.md` / `CLAUDE.md` 声明、已有项目配置、探测 `.trellis/spec/`。确认绝对路径位于对应项目内；确实无法确定时才询问。
- 优先使用 `wiki_sync_specs`、`wiki_manage_shared_spec` 及 `wiki_list` / `wiki_get`。写操作的 preview 显式绑定 `project`、适用的 `source_root` 或公共页路径；apply 使用该计划的 `plan_id`。`wiki_sync_specs` 只支持项目到知识库，不能把知识库改动推回项目。
- 工具未暴露、需要备用入口，或写入会碰到已知限制时，读取[同步与工具契约](references/sync-contract.md#工具入口与失败恢复)。

## 共同约束与授权

- 公共规范固定为扁平路径 `wiki/entities/shared-specs/<file>.md`，用 `applies_to.languages`、`applies_to.platforms`、`applies_to.frameworks` 和 `conditions` 表达适用范围。
- 初次提取可追溯到项目规则。已确认的公共正文可独立修订、去重、拆分或合并；区分来源原文、平台契约、工程原则及公司或项目策略，编辑后的正文标明其性质。
- 按 Vault schema 记录真实 raw 来源与内容哈希，分别标明镜像、用户确认、官方依据的证据性质。文档核对不等于账号实测。不要为了「补齐」来源而重报 `sources`，以免把 `freshness` 或 `provenance_unverified` 带偏。
- 写入前准备完整 diff、目标、适用条件、来源及删除或引用影响。按用户要求的审核粒度执行：只要求分析或逐项确认时先呈现候选；已明确要求检查修订、合并或同步时，该范围内的可逆文档变更可在预览核对后落实，包括必要的新文件、索引、引用迁移及被替代旧页清理，无需为这些步骤重复确认。准入、降级或扩大影响范围时，仍须先确认。
- 新任务重新审核适用性与差异，不沿用旧选择作为新授权。授权按任务目标、项目、规则语义及影响判断；超出范围、未决的规则取舍或影响扩大时，展示具体变化并确认。遇到 `source_changed` / `target_changed` 保留现场、重新预览；结果仍在既有授权内时可继续，等结果修复和重试同理。计划有短时有效期，过期或 `current_hash` 已变时重新出 preview，不得 apply 过期计划。
- 审核选择只用于当前任务，不创建 Trellis task，也不将选择、旧正文或审核状态写成项目或知识库历史。失败恢复所需的工具计划按其生命周期处理。
- 不要改手写的历史日志。带有生成标识的知识库导航由服务投影维护，写入后调用 `refresh_navigation`，不要用 `wiki_update` 改生成 `index.md`。用户未要求时不 git commit。

## `extract`：提取、维护和降级公共规范

1. 按 heading 或规则边界读取项目规范并拆分候选，先用「准入与最小化」判断是否应留在项目内。维护现有公共正文时读取其完整内容、范围和来源，并同样复核准入条件；不再满足的列入降级，而不是直接更新后保留。
2. 用 `wiki_list` 完整枚举公共页，结合稳定路径、`derived_from`、标题及正文判断对应关系。相似标题不足以合并或提升；已有独立正文先比较语义，保留有效来源集合。
3. 通过准入的候选指定扁平路径、适用范围、`conditions` 和 `derived_from: {project, path, rule}`。新增真实来源追加到集合；失效或已迁移的来源按当前证据处理。未通过准入的候选给出项目落点（踩坑记录或项目规范）及理由，不创建公共页。
4. 通过准入的项逐项调用 `wiki_manage_shared_spec(operation="upsert" 或 "delete", action="preview", ...)`，展示正文、范围及来源差异，按用户指定的审核粒度决定新建、更新、删除、降级或舍弃；已有授权按共同规则落实。补写 `source_hashes` 或保留已有来源哈希时，不要用 `wiki_manage_shared_spec` 作为最终写入，改走[同步与工具契约](references/sync-contract.md#工具入口与失败恢复)中的安全写法。
5. apply 前核对候选、准入结论和来源版本。只 apply 获授权的计划；舍弃用同工具 `action="discard"`。拆分、合并、移动或降级时同时读取[文档迁移](references/document-migration.md)。

## `import`：公共规范回写项目

执行前读取[项目采用与适配](references/project-adoption.md)。

1. 确定项目环境和采用策略，完整枚举并读取公共页，逐条审核适用性。项目未实现该能力，或该页按最小化应留在其他项目时，不导入、不改链到替代页。
2. 按请求选择原文导入或项目适配，结合现有目录、索引和规则语义提出目标位置及完整差异。公共规范已合并、降级或归档的，项目副本做同样处理。
3. 落实获授权的结果，回读核对规则语义及项目索引。涉及多页整合、移动、删除或降级时读取[文档迁移](references/document-migration.md)。
4. 用户要求把项目规范镜像回知识库时，再进入 `sync`。项目回写不会反向删除公共页。

## `sync`：项目镜像到知识库

执行前读取[同步与工具契约](references/sync-contract.md)；涉及源页删除、移动、拆分、合并或降级时同时读取[文档迁移](references/document-migration.md)。

1. 对真实 `source_root` 调 `wiki_sync_specs(project=..., source_root=..., action="preview")`。
2. 展示工具返回的 create、update、delete、unchanged 计数及变更路径，并补足正文和元数据差异；区分本次编辑、既有未同步差异与知识库独有内容。确认全部实际影响处于授权范围。
3. 元数据归属或其他阻碍已解决后，用同一 `plan_id` apply。源目录删除会删除对应镜像页；公共实体独立维护，其引用按迁移流程复核。
4. 按同步契约验收文件、引用和投影状态；失败报告已完成部分与恢复入口。

## 完成标准

所有获授权的变更均已落地，其他页面保持不动；回读结果与审核内容相符，手工索引和活动引用有效，且不把已清理的项目规范改链到替代页。同步后源与镜像符合明确的内容及元数据契约，相关导航与检索投影成功；未完成的投影、来源迁移或同步分别明确报告，不能仅凭文件已写入宣称完成。

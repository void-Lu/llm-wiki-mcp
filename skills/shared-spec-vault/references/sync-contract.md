# 同步与工具契约

进入 `sync` 或工具不可用、同步失败时读取。

## 内容与元数据归属

现有镜像契约是完整文件镜像：按源、目标完整文件内容比较并覆盖，源缺失则删除目标。不能假定服务会合并或保留目标 frontmatter。

预览时把正文差异与 frontmatter 差异分开，识别知识库独有内容及字段，如 `freshness`、`provenance_unverified`、来源和来源哈希。字段归属按当前 Vault schema 与服务契约判断，不能仅凭字段名称推定可覆盖或可保留。

知识库独有内容与严格镜像冲突时，先核对是否已有明确的归属及受支持处理方案：

- 严格文件镜像：知识库专属元数据按已确定方案存放在镜像文件之外。
- 正文镜像并由服务管理元数据：仅在服务实际支持且字段归属明确时使用，比较和验收遵循该契约。

以上是两种可选契约，不是已实现能力。没有可执行方案时保持受影响目标不动，报告阻碍并继续不依赖该同步的工作；需要改变内容归属时提出具体方案供用户决定。整树计划不支持按页排除时，保持该项目的计划未应用，不能私改计划实现跳过。使用真实项目规范目录作为 `source_root`，不以拼入知识库字段的临时目录冒充来源，也不把这些字段回灌项目来消除差异。

## 预览与范围

工具返回的计数和计划为准，检查实际变更文件集合。将变更区分为本次编辑、此前未同步差异及知识库独有内容；完整目录同步可能包含三者，不能把附带变化隐入总数。

preview 只有路径和哈希时，读取源目标并补足正文及元数据 diff。用户明确要求整目录同步时，既有的普通源目标差异属于同步范围，可在核对预览后执行；涉及额外规则取舍或知识库独有内容时，分别按授权及内容归属处理。

## 工具入口与失败恢复

优先发现实际暴露的 Wiki 工具。未暴露时，查服务仓库文档及公开 CLI 的帮助，选择受支持入口；通过 CLI 提交 preview/apply 时保持相同的差异、版本校验和投影语义。不要硬编码个人服务仓库路径，或用直接调用内部类、手工覆写知识库来替代缺失的工具契约。

没有受支持写入入口时可继续只读盘点、准备审核差异，并完成不依赖该入口的已授权本地修改；明确镜像尚未执行。不要为了使用 skill 而修改服务或安装工具。

失败时读取工具返回的已完成页面、失败阶段、计划或操作标识。遇到投影修复状态，使用工具支持的修复或重试入口；遇到源目标漂移，重新预览并核对授权。按计划中实际完成的状态恢复，避免重复创建页面或覆盖漂移内容。

## 验收与收尾

- 核对源和镜像的文件集合与新增、删除集合。严格镜像逐文件核对完整内容；已支持元数据分离的契约分别核对正文一致性和受管理字段。
- 完成后再预览应无意外差异；若检查创建了无变更计划，使用受支持的 discard 结束它。重复出现同一元数据差异说明同步契约仍未解决。
- 按[文档迁移](document-migration.md)核对受影响的索引、活动链接和公共来源。读取服务的导航、检索及来源投影结果或状态；已有增量投影成功时无需再做全库重建。
- 成功或明确舍弃后清理本次临时文件及已结束计划；待恢复计划保留到修复完成，不删除其他任务的计划。工具自身写入的正常审计记录遵循 Vault 政策，不视为 skill 保存审核状态。

元数据归属校验、变更集合核对、漂移拒绝和投影恢复应由服务提供确定性保障。能力缺失时说明实际限制；skill 的人工核对不等于这些保障已实现，服务升级需另有任务授权。

# 文档迁移

在项目或公共规范发生合并、拆分、改名、移动或删除时读取。

## 准备迁移

- 为每个旧文件或规则章节指定新文件及对应章节；纯删除说明处置理由。合并时覆盖有效规则、适用条件、例外和必要案例，对实质删减单独列明。
- 列出新增、更新、删除集合，以及手工索引、活动正文链接、章节锚点和 `derived_from` 的受影响位置。需要枚举旧路径全部引用时执行精确全文查找，不只查看目录索引。
- 历史审计记录与不可变 raw 快照保留原始内容，单独识别；活动正文或索引中的引用迁移到最终位置。为保留历史而创建旧规范副本不属于镜像同步。

## 来源与链接

公共页不会因项目源页被删而自动删除。对每个引用旧页的公共页判断：

- 同一规则迁移到新位置且证据仍成立：保留独立正文，更新 `derived_from.path` 和 `rule`，核对新页内容，保留真实历史 raw 来源。
- 来源消失但公共正文仍应保留：按审核结论移除失效的当前来源关联，保持真实证据及其边界；来源减少不能自动提升证据状态。
- 规则本身变化或失去适用性：分别提出修订或删除方案，按公共页 preview/apply 流程落实。

迁移后的项目规则是公共规范的应用结果时，不将这次应用自动追加为公共规则的独立原始证据。仅更新文件或章节位置，不据此改写历史快照及其哈希。

源目录的手工 spec index 随内容更新；带有生成标识的知识库导航由服务投影维护。活动链接迁移时同时验证目标文件和章节存在，避免只替换文件名。

## 执行与完成

把来源和引用变更纳入同一迁移方案，并按各工具支持的粒度安排执行。项目整树同步会同时创建新镜像和删除旧镜像，应预先准备公共页后续修订；其新 `derived_from` 目标须在提交公共页变更时存在。公共页修订失败时明确报告待修复引用，不把迁移标为完成。

验收：新文档覆盖审核后的规则，旧文件按计划移除，手工索引和活动链接指向最终位置，受影响公共页的来源关联有效，生成导航反映最终结构。若没有受影响的公共引用，直接记录核查结论，无需生成来源变更。

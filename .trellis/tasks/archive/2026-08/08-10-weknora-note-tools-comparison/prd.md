# WeKnora 知识库笔记工具对比分析

## Goal

基于 Tencent/WeKnora 官方仓库的可追溯源码证据，系统梳理其中与知识库笔记创建、查询、维护相关的脚本与调用链，并与当前本地 `llm-wiki-mcp` 提供的 MCP 工具逐项比较，形成一份可直接指导本地工具演进的完整中文文档。

## Background / Confirmed Facts

- 外部对照对象为用户指定的官方仓库：`https://github.com/Tencent/WeKnora.git`。
- WeKnora 比较基线已锁定为默认分支 `main` 的提交 `355d161d644793e6d7613ab34ef0aad610f9f9bf`（访问日期：2026-08-10）。
- 本地对照对象为当前工作区 `llm-wiki-mcp`，以当前分支和工作树实际代码为准。
- 本地调研起点为分支 `v0.9.21`、HEAD `19bac922c31932efc1edc5e9d99d186394a36158`；调研期间 `path_prefix` 修复由并行工作独立提交，最终比较基线为 `0e0484839617513fcaba1bf4c6d934968d8515ae`。最终工作树仅有与本任务无关的未跟踪目录 `.netsuite-mcp/`。
- 本地 core profile 的公开 MCP 工具已确认共 8 个：`wiki_status`、`wiki_ingest`、`wiki_codegraph_import`、`wiki_write_note`、`wiki_update`、`wiki_query`、`wiki_archive`、`wiki_restore`。
- 研究范围聚焦知识库笔记的创建、查询和维护，不扩展为 WeKnora 全量架构评审。
- 所有关于 WeKnora 的关键结论必须引用官方源码、官方文档或官方提交等一手来源，并记录所分析的提交版本。
- 最终交付物为 `docs/researches/weknora-knowledge-note-tools-comparison.md`；规划/研究中间资料保存在本 Trellis 任务目录。

## Requirements

- R1：识别 WeKnora 中与知识库/知识条目创建、导入、解析、更新、删除、检索、列表、详情、状态维护有关的脚本、入口、核心服务和数据模型。
- R2：识别本地 MCP 中对应的工具定义、参数契约、实现调用链、存储约束、测试与文档。
- R3：按能力域建立可核验映射，至少覆盖创建、查询、维护三个主维度，并明确“直接对应、部分对应、缺失或不适用”。
- R4：比较接口契约、内容/元数据模型、检索能力、批量操作、生命周期与状态、错误处理、安全与权限、可观测性、测试和文档等维度。
- R5：列出本地工具可优化项；每项包含源码证据、现状/差距、建议、预期收益、复杂度或风险、优先级，避免把产品定位差异误报为缺陷。
- R6：文档中的文件路径、符号名、工具名、参数名和关键行为应能回溯到具体源码；外部源码使用稳定的提交固定链接。
- R7：保存一份完整、自洽、可独立阅读的中文 Markdown 文档，不依赖聊天记录理解。

## Scope Boundaries

### In Scope

- WeKnora 知识库及知识条目/文档层面的创建、查询、更新、删除和状态维护代码。
- 与上述能力直接相关的 API/处理器、服务、仓储/模型、任务或脚本、配置与测试。
- 本地 MCP 暴露给调用方的知识库笔记工具及其直接依赖。
- 基于证据的差距分析和分级优化建议。

### Out of Scope

- WeKnora 聊天 UI、模型训练、通用部署运维等与知识库笔记生命周期无直接关系的模块。
- 直接修改本地 MCP 的产品代码；本任务只交付分析文档。
- 对 WeKnora 做运行时性能压测、部署或安全渗透测试。
- 将 WeKnora 的所有功能机械照搬到本地；建议需考虑两者定位与边界差异。
